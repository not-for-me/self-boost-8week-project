## 배운 것

### 1. Bloom Filter - "확실히 없다"의 가치

```
False Positive: 있다고 했는데 없을 수 있음 (확률 조절 가능)
False Negative: 절대 없음 - "없다"면 확실히 없음
```

**실제 활용**: C4 데이터셋 URL 중복 체크
- Hash Set: ~40GB (10억 URL)
- Bloom Filter (1% FPR): ~1.2GB (33배 절약)

### 2. MinHash + LSH - "유사한 것끼리 모으기"

Near-duplicate detection 문제:
- Naive: O(N²) 비교 (10억 문서 → 불가능)
- MinHash + LSH: 후보 쌍만 비교 (실용적)

**핵심 원리**:
```
MinHash: 문서 → 고정 크기 signature (Jaccard 유사도 보존)
LSH: 유사한 signature → 같은 bucket (후보 필터링)
```

### 3. 4가지 자료구조의 LLM 파이프라인 역할

| 자료구조 | 역할 | 단계 |
|---------|------|------|
| **Trie** | 토큰 사전 관리 | Tokenization |
| **Suffix Array** | 빈번 패턴 탐색 (BPE) | Tokenization |
| **Bloom Filter** | URL/문서 ID 중복 체크 | Data Collection |
| **MinHash** | Near-duplicate 탐지 | Deduplication |
